## Деструктуризация объекта в параметрах

Раньше мы доставали свойства из объекта внутри функции через точку:

**Пример 1**
```js
function getTitle ( book ) {
    return book.title
}

console.log( getTitle ( { title: "Мастер и Маргарита", pages: 500 } ) ) // "Мастер и Маргарита"
```
Это работало, но если нужно достать несколько свойств, код становится длинным:

**Пример 2**
```js
function getInfo ( user ) {
    return user.name + ", " + user.age + " лет"
}
```
Деструктуризация позволяет "распаковать" объект прямо в параметрах функции и сразу получить переменные с нужными именами:

**Пример 3**
```js
function getTitle ( { title } ) {
    return title
}

console.log( getTitle ( { title: "Мастер и Маргарита" } ) ) // "Мастер и Маргарита"
```
Здесь `{ title }` означает: "возьми объект, который передадут, достань из него свойство `title` и положи его значение в переменную `title`". Дальше можно использовать эту переменную как обычно

**Пример 4. Несколько свойств**
```js
function introduce ( { name, age } ) {
    return `${name}, ${age} лет`
}

console.log( introduce ( { name: "Борис", age: 25 } ) ) // "Борис, 25 лет"
```

**Значения по умолчанию**: если свойства может не быть, задаём значение по умолчанию:

**Пример 5**
```js
function greet ( { name = "гость" } ) {
    return "Привет, " + name
}

console.log( greet ( { name: "Вика" } ) ) // "Привет, Вика"
console.log( greet ( {} ) )               // "Привет, гость"
```

**Задача 1. Принимает объект корзины и возвращает общую стоимость**
```js
function getCartTotal ( { items, price } ) {
    return items * price
}

console.log( getCartTotal ( { items: 3, price: 100 } ) ) // 300
```
Мы просто распаковали `items` и `price` и перемножили их

**Задача 2. Принимает объект пользователя с необязательным полем name**
```js
function greetUserZd ( { name } ) {
    return `Привет, ${name ?? "гость"}!`
}

console.log( greetUserZd ( { name: "Анна" } ) ) // Привет, Анна!
console.log( greetUserZd ( {} ) )               // Привет, гость!
```
Использовали метод про который можно почитать [тут](типы-данных-и-операторы/2026-06-28-03-вопрос-и-два-вопроса.md)

Если коротко, то `??` - это “Если слева null или undefined - возвращает правое значение. Иначе - левое”

**Задача 3. Возвращает название города. Использовать вложенную деструктуризацию**
```js
function getCity ( { address: { city } } ) {
    return city
}

console.log( getCity ( { name: "Анна", address: { city: "Москва" } } ) ) // Москва
```

Что будет если написать просто `getCity( { city } )`?
Не получится, ведь тогда `city` будет искать `city` на верхнем уровне объекта, а он лежит внутри `address` и выведет `undefined`

А если просто написать `address`?
Тогда `address` даст тебе весь вложенный объект целиком, то есть если мы напишем
```js
return address
```
То выведет `{city: 'Москва'}`

**Задача 4. Принимает объект книги с полями title и author. Нужно вернуть строку "Название - Автор". Использовать вложенную деструктуризацию и переименование**
```js
function getBookInfoZf ( { title, author: { name: authorName, surname: authorSurname } } ) {
    return `${title} - ${authorName} ${authorSurname}`
}

console.log( getBookInfoZf ( { title: "Война и мир", author: { name: "Лев", surname: "Толстой" } } ) ) // Война и мир - Лев Толстой
```

Но что будет если написать `${title} - ${name, surname}`? Я знал что не получится, но не знал как доказать
В итоге я понял, что `,` это оператор который возвращает правое значение, то есть запятая - это оператор, который выполняет левую часть, потом правую, и возвращает правую. Углубляться не нужно, просто запомнил что лучше так не писать и на этом хватит

**Задача 5. Принимает объект прямоугольника с полями width и height, где height может отсутствовать (тогда считаем, что это квадрат). Вернуть площадь**
```js
function getRectangleArea ( { width, height = width } ) {
    return width * height
}

console.log( getRectangleArea ( { width: 10, height: 5 } ) ) // 50
console.log( getRectangleArea ( { width: 7 } ) )             // 49
```
`height = width` в параметрах функции делает значение по умолчанию — оно срабатывает, только если свойство отсутствует или `undefined`

А если написать без значения по умолчанию, но так:
```js
return width * height ?? width
```
Вернет `NaN`, потому что сначала посчитается `width * height`, потом `??` сравнит результат с `null`/`undefined`. Если `height` не передан, он будет `undefined`, и `width * undefined` даст `NaN`. `NaN ?? width` - `NaN` это не `null`/`undefined`, так что вернётся `NaN`

А если написать
```js
width * (height ?? width)
```
Так можно, если `height` не передан, он `undefined`, и `height ?? width` даст `width`. Площадь посчитается верно, но значение по умолчанию в параметрах (`height = width`) чище - один раз задал и забыл

Почему у меня стоит пробел между словом и скобкой? Просто для читаемости, можно и без пробелов

**Переименование в деструктуризации**

Бывает, что имя свойства объекта неудобное или конфликтует с другой переменной или приходит откуда-то извне. Тогда мы берём свойство, но кладём его в переменную с другим именем

```js
// Объект приходит с короткими ключами:
let book = { t: "Мастер и Маргарита", p: 500 }

// Без переименования - нечитаемо, а с переименованием - понятно:
function getInfo ( { t: title, p: pages } ) {
    return `${title} - ${pages} страниц`
}

console.log( getInfo ( book ) ) // "Мастер и Маргарита - 500 страниц"
```

**Задача 1. Объект имеет fn (имя) и ln (фамилия). Переименуй и верни "Имя Фамилия"**
```js
function introduce ( { fn: firstName, ln: lastName } ) {
    return `${firstName} ${lastName}`
}

console.log( introduce ( { fn: "Иван", ln: "Петров" } ) ) // Иван Петров
```

А если написать `return ${fn} ${ln}`?
Будет ошибка, ведь переменных до знака `:` уже не существует
