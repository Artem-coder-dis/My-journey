### Этап 1: Неявная привязка

Метод - это функция внутри объекта. `this` в методе ссылается на объект, которому принадлежит метод

```javascript
let user = {
    name: "Анна",
    greet() {
        return "Привет, " + this.name
    }
}

console.log(user.greet()) // "Привет, Анна"
```

`this.name` - это `user.name`. То есть `this` - это объект перед точкой в момент вызова

**Задача 1.** Напиши объект `book` с полями `title` и `author` и методом `getDescription()`, который возвращает строку "Название - Автор"

```javascript
let book = {
    title: "Война и мир",
    author: "Толстой",
    getDescription() {
        return `${this.title} - ${this.author}`
    }
}

console.log(book.getDescription()) // "Война и мир - Толстой"
```

В переменной создаём объект  
`title` и `author` - это свойства объекта, в конце обязательно ставим запятую, а то будет ошибка  

`getDescription()` - это просто название функции, я сначала думал, что это и правда какой-то метод  
`return '${this.title} - ${this.author}'` - собирает строку из 3 частей: название, тире, автор

### Этап 2: Проблема потери this

Когда метод вытаскивают из объекта и вызывают отдельно, `this` ломается

```javascript
let user = {
    name: "Анна",
    greet() {
        return "Привет, " + this.name
    }
}

// правильно - метод вызывается прямо у объекта, this знает, кто он:
console.log(user.greet()) // "Привет, Анна"

// неправильно - метод вытащили в переменную и вызвали без объекта:
let f = user.greet
console.log(f()) // Ошибка. this потерян, он undefined
```

Как правильно сохранять: если хочешь сохранить метод и потом вызвать, сохраняй вместе с объектом и вызывай через точку:

```javascript
let saved = user         // сохранили объект целиком
console.log(saved.greet()) // "Привет, Анна" - работает
```

А если написать `console.log(user)`  
Выведется сам объект: `{ name: "Анна", greet: [Function: greet] }`

**Задача 1.** Напиши объект `car` с `brand` и методом `getBrand()`. Сохрани метод в переменную `f` и вызови `f()`. Объясни, почему ошибка

```javascript
let car = {
    brand: "Tesla",
    getBrand() {
        return this.brand
    }
}

let f = car        // сохранили объект целиком
f()                // TypeError: f is not a function
```

Почему происходит ошибка: `f` - это объект, не функция. Нельзя вызывать объект через скобки. Правильно: `f.getBrand()`

```javascript
// правильно - вызываем метод прямо у объекта:
console.log(car.getBrand()) // "Tesla"

// неправильно - вытащили метод и вызвали отдельно, this потерян:
let f = car.getBrand
console.log(f()) // ошибка

// правильно - сохранили объект целиком, потом вызвали метод:
let saved = car
console.log(saved.getBrand()) // "Tesla"
```

Два правильных способа: вызывать у исходного объекта или сохранить объект целиком и вызывать у него. Неправильный - сохранить только метод без объекта

### Этап 3: Жёсткая привязка (bind)

Теперь, когда мы увидели проблему, следующий шаг - как её исправить. Есть 2 способа:

1. Сохранить объект целиком (уже разобрали)
2. Использовать `bind` - привязать метод к объекту навсегда

```javascript
let f = car.getBrand.bind(car)
console.log(f()) // "Tesla" - работает, this привязан
```

`bind(car)` создаёт новую функцию, у которой `this` навсегда равен `car`. Неважно, как её вызовут потом - `this` не потеряется

**Задача 1.** Дан объект `counter` с `count: 0` и методом `increment()`. Сохрани метод через `bind` и вызови несколько раз. `count` должен увеличиваться

```javascript
let counter = {
    count: 0,
    increment() {
        return this.count++
    }
}

let inc = counter.increment.bind(counter)
console.log(inc()) // 0
console.log(inc()) // 1
console.log(inc()) // 2
```

Тут у меня возникло 3 основных вопроса:

**1. Почему именно такая структура `counter.increment.bind(counter)`, что происходит**

Что вообще такое `this`, подробнее  
`this` - это местоимение «этот». Как в жизни: «этот стол», «этот дом». В JS `this` означает «тот объект, с которым сейчас работаем»

Когда ты внутри метода пишешь `this.count`, ты говоришь «возьми `count` у этого объекта». Какого «этого»? Того, перед точкой при вызове

`counter` - это объект: `{ count: 0, increment: [Function] }`  
`counter.increment` - это метод, функция внутри объекта. Если написать просто `counter.increment`, это ссылка на функцию: `function() { return this.count++ }`. Но пока её не вызвали, она просто лежит

> **1.1 Что вообще за ссылка? Что значит лежит пока не вызвали?**
> 
> Ссылка. Функция `increment` живёт в памяти. `counter.increment` - это не сама функция, а путь к ней. Ты говоришь: «вот эта функция, которая лежит в объекте `counter` под именем `increment`». Ты её не вызываешь, просто показываешь на неё пальцем. Это и есть ссылка
> 
> "лежит". Рецепт на бумажке. Ты его написал и положил в коробку. Он просто существует. Ты можешь его прочитать, передать другу, приклеить к нему стикер - но еду по нему ещё не готовили. Он «лежит» - ждёт, когда его вызовут
> 
> В коде то же самое: пока нет скобок `()` - функция не выполняется. Она просто хранится в памяти. Ты можешь её передать, сохранить в переменную, привязать `bind`. Но только скобки запускают код внутри
> 
> ```javascript
> let f = counter.increment  // ссылка - рецепт в руке, не готовим
> f()                       // вызов - начали готовить
> ```

`.bind(counter)` - метод `bind` берёт функцию и приклеивает к ней `this` навсегда. Он создаёт новую функцию, у которой `this` всегда будет равен `counter`. Возвращает эту новую функцию

> **1.2 Как это, приклеивает навсегда?**
> 
> `bind` - это клей. Ты берёшь бумажку с рецептом и клеишь на неё стикер: «ЭТА коробка - вот та, с полки №3». Теперь, кто бы ни взял эту бумажку и ни начал готовить, он всегда будет знать: «эта коробка» = та самая, с полки №3
> 
> ```javascript
> let f = counter.increment.bind(counter)
> // бумажка с рецептом + приклеенный стикер «коробка = counter»
> ```
> Теперь `f` - это та же функция `increment`, но с намертво приклеенным `this = counter`

Без `bind`: если вытащить `counter.increment` в переменную и вызвать, `this` потеряется и будет `undefined`. С `bind`: `this` намертво прибит к `counter`, вызывай как хочешь - `this` не потеряется

> **1.3 Вызывай как хочешь - что это значит?**
> 
> Функцию можно вызвать по-разному:
> ```javascript
> f()                    // просто вызов
> setTimeout(f, 1000)    // как колбэк
> arr.map(f)             // как колбэк в метод массива
> ```
> Без `bind` - в каждом из этих вызовов `this` потерялся бы. С `bind` - `this` всегда `counter`, неважно, как вызвали. Клей держит

> **1.4 Мы просто возвращаемся выше чтобы взять `count`? Но почему?**
> 
> Да. `this.count` - это «пойди в объект, который вызвал метод, и возьми у него свойство `count`»
> 
> `this` - это не сама переменная `count`. Это путь к ней. Как адрес на коробке. Ты говоришь: «иди в ЭТУ коробку и принеси то, что внутри»
> 
> Без `this` - `count` ищется как переменная. Её нет. Ошибка. С `this` - `this.count` ищется как свойство объекта. `this` знает, в каком объекте искать, потому что метод вызван через точку от этого объекта
> 
> Так что да, мы возвращаемся в объект, берём значение, возвращаем. `this` - это мост между методом и объектом, которому метод принадлежит

> **1.5 Но `count` объявлен выше, значит `count++` должен видеть что берёт**
> 
> `count` объявлен как свойство объекта, а не как переменная
> 
> ```javascript
> let counter = {
>     count: 0,        // это свойство объекта, не переменная
>     increment() {
>         return this.count++  // this.count - свойство, count - переменная (её нет)
>     }
> }
> ```
> Переменная - это когда `let count = 0`. Тогда `count` виден внутри функции. Свойство объекта - это `counter.count`. Без `this` или `counter.` к нему не обратиться
> 
> Внутри `increment` нет переменной `count`. Есть только свойство `this.count`. Поэтому `count++` даёт ошибку - JS ищет переменную, не находит, а `this.count++` работает - JS идёт в объект и увеличивает свойство
> 
> Свойство и переменная - разные вещи. Свойство принадлежит объекту. Переменная - просто имя в коде. `this` говорит: «это свойство, ищи в объекте». Без `this` JS думает, что это переменная

Итог цепочки: `counter.increment.bind(counter)` - «возьми метод `increment` из объекта `counter` и создай его копию, у которой `this` навсегда указывает на `counter`». Результат - функция, готовая к безопасному вызову

**2. Почему, убрав `this.`, выводит ошибку `count is not defined at Object.increment`, ведь `return` возвращает**

Когда мы пишем просто `count++`, JS ищет переменную с именем `count` внутри функции или снаружи, если не находит - ошибка. `this.count` говорит: «возьми свойство `count` у объекта, на который ссылается `this`». Без `this` JS не знает, что `count` - это свойство объекта

**3. Я попробовал написать `return this.count + 1`, но вывод был 1 1 1, а когда `++`, то вывод 0 1 2, почему так**

`this.count++` - увеличивает свойство `count` в объекте и возвращает старое значение. Было 0 -> вернул 0, стало 1. В следующий раз было 1 -> вернул 1, стало 2. Объект меняется

`this.count + 1` - читает свойство `count` (которое всегда 0) и возвращает `0 + 1 = 1`. Но само свойство `count` не меняется - оно так и остаётся 0. Поэтому каждый раз 1

`++` меняет оригинал. `+ 1` не меняет

**Задача 2.** Дан объект `calc` с полем `value = 10` и методами `add(n)` и `mult(n)`, которые увеличивают/умножают `value` на `n` через `this` и возвращают результат. Вызвать `add(5)`, потом `mult(2)`

```javascript
let calc = {
    value: 10,
    add(n) {
        return this.value += n
    },
    mult(n) {
        return this.value *= n
    }
}

console.log(calc.add(5))  // 15
console.log(calc.mult(2)) // 30
```

Здесь мы пишем методы `add` и `mult` с их параметрами `n`. `n` пишем без `this` потому что это параметр функции, а не свойство объекта. Далее выводим в консоль `calc.add(5)` и присваиваем значение 5, то есть в объекте 10 + 5, сохраняем результат и потом умножаем на 2

**Задача 3.** Дан объект `counterA` со свойством `count = 0` и методом `increment()`. Дан объект `counterB` со свойством `count = 100`. Через `bind` привяжи метод `increment` из `counterA` к объекту `counterB`. Вызови привязанную функцию три раза и выведи результат каждого вызова

```javascript
let counterA = {
    count: 0,
    increment() {
        return this.count++
    }
}

let counterB = {
    count: 100
}

let incB = counterA.increment.bind(counterB)

console.log(incB()) // 100
console.log(incB()) // 101
console.log(incB()) // 102
```

Почему теперь пишем так `counterA.increment.bind(counterB)`  
Раньше в скобках был первый объект, потому что метод был из того же объекта и мы привязывали его к себе же чтобы не потерять. А теперь метод из `counterA`, но мы хотим, чтобы он работал с `counterB`. Поэтому в `bind` передаём `counterB` - говорим: "возьми метод из A, но `this` пусть указывает на B"

Правило простое: в скобках `bind(тотОбъектСкоторымРаботаем)`

**Задача 4.** Дан объект `user` с полями `name` и `age` и методом `introduce()`, который возвращает строку "Меня зовут name, мне age лет". Сохрани метод в переменную `intro` через `bind`. Вызови `intro()` и выведи результат. Потом измени возраст пользователя напрямую (`user.age = 30`) и снова вызови `intro()`. Должен измениться вывод

```javascript
let user = {
    name: "Анна",
    age: 25,
    introduce() {
        return `Меня зовут ${this.name}, мне ${this.age} лет`
    }
}

let intro = user.introduce.bind(user)
console.log(intro()) // Меня зовут Анна, мне 25 лет

let userAge = {
    age: 30,
    name: "Анна"
}
let introAge = user.introduce.bind(userAge)
console.log(introAge()) // Меня зовут Анна, мне 30 лет
```

Зачем мы присваиваем имя если мы меняем только возраст?  
Потому что в объекте `userAge` нет свойства `name`, `bind` привязывает метод ко второму объекту. Мы передали только `age: 30`. Если во втором объекте нет свойства `name`, то `this.name` вернёт `undefined`, и в строке будет "Меня зовут undefined, мне 30 лет"  

Но почему тогда передаётся шаблонная строка **"Меня зовут , мне лет"** и мы не прописываем её заново?

Когда мы вызываем `introAge()`, JS заходит в этот же метод и снова строит строку. Шаблонная строка уже написана внутри метода. `bind` не пересоздаёт метод, он только подменяет `this`. Поэтому код метода выполняется снова, строка собирается заново с теми значениями, которые есть во втором объекте. Прописывать `return` заново не нужно - он уже есть в методе

### Этап 4: Явная привязка (call / apply)

Для 1-ой работы эту тему можно пройти поверхностно, `call` / `apply` - раньше использовались часто, сейчас реже. Достаточно знать, что они существуют и делают то же, что `bind`, но с мгновенным вызовом

**call**

`call` вызывает функцию и первым аргументом передаёт, чему равен `this`. Остальные аргументы - параметры функции через запятую

```javascript
function greet(greeting, punctuation) {
    return `${greeting}, ${this.name}${punctuation}`
}

let user = { name: "Анна" }
let user2 = { name: "Антон" }

console.log(greet.call(user, "Привет", "!"))  // "Привет, Анна!"
console.log(greet.call(user2, "Привет", "!")) // "Привет, Антон!"
```

По шагам:  
1. `greet.call` - говорим: «вызови функцию `greet`, но с особым `this`»  
2. Первый аргумент `user` - становится `this`, `this.name = "Анна"`  
3. `"Привет"` попадает в параметр `greeting`  
4. `"!"` попадает в `punctuation`  
5. Выполняется и возвращает `"Привет, Анна!"`

Если появится `user2` - просто передаём новый объект, функция та же

Негибкий вариант (так нежелательно):

```javascript
function greet(greeting) {
    return `${greeting}, ${user.name}!`  // привязана к конкретному user
}
```

**Задача 1.** Дан объект `counter = {count: 0}`. Дана функция `increment()`, возвращающая `this.count++`. Вызови `increment.call(counter)` три раза и собери результаты в массив

```javascript
function increment() {
    return this.count++
}

let result = []
let counter = { count: 0 }

for (let i = 0; i < 3; i++) {
    result.push(increment.call(counter))
}

console.log(result) // [0, 1, 2]
```

Что происходит: сначала объявили функцию (не вызвали), потом создали массив и объект. В цикле через `call` передаём `counter` как `this`. Каждый вызов возвращает текущее `count` (0, 1, 2) и пушится в массив

**apply**

`apply` делает то же, что `call`, но аргументы передаёт массивом

```javascript
func.call(thisArg, arg1, arg2, arg3)     // запятая
func.apply(thisArg, [arg1, arg2, arg3])  // массив
```

```javascript
function greet(greeting, punctuation) {
    return `${greeting}, ${this.name}${punctuation}`
}

let user = { name: "Анна" }
console.log(greet.apply(user, ["Привет", "!"])) // "Привет, Анна!"
```

По шагам: первый аргумент - `this`, второй - массив аргументов, `apply` разбирает его по параметрам

**Задача 2.** Дана функция `sum(a, b, c)`, возвращающая `this.base + a + b + c`. Есть объект `ctx = {base: 100}`. Посчитай сумму через `apply`

```javascript
function sum(a, b, c) {
    return this.base + a + b + c
}

let ctx = {base: 100}
console.log(sum.apply(ctx, [10, 20, 30])) // 160
```

**Задача 3.** Дана функция `sum(a, b)`. Есть три объекта: `ctx1 = {base: 10}`, `ctx2 = {base: 20}`, `ctx3 = {base: 30}`. Создай массив `contexts = [ctx1, ctx2, ctx3]`. Пройди по нему циклом и для каждого вызови `sum` с аргументами `[5, 5]` через `apply`. Собери результаты в массив -> `[20, 30, 40]`

Сначала я написал неправильно: вызывал `apply` на весь массив, и внутри функции пытался циклом пройти по объектам, но элементы были объектами, а не числами. Плюс забыл `this`

Правильно:

```javascript
function sum(a, b) {
    return this.base + a + b
}

let ctx1 = {base: 10}
let ctx2 = {base: 20}
let ctx3 = {base: 30}
let contexts = [ctx1, ctx2, ctx3]

let result = []
for (let i = 0; i < contexts.length; i++) {
    result.push(sum.apply(contexts[i], [5, 5]))
}

console.log(result) // [20, 30, 40]
```

Цикл снаружи, функция чистая, `apply` передаёт `this` и массив аргументов для каждого объекта

`apply` от `call` ничем не отличается кроме способа передачи аргументов

### Этап 5: Стрелочные функции и this

Хочу сказать, что 5-ый этап самый важный, только на его написание и отработку у меня ушло 3 дня (~13 часов практики, теории и написания поста) и на 1-ой работе когда будешь работать с объектами и методами массивов внутри них, будет работать правило "метод - обычная функция, колбэк - стрелка"

Стрелочные функции не имеют своего `this`. Они берут `this` из того места, где были созданы - из внешней области видимости

**Пример 1.** Обычная функция (всё работает):
```javascript
let user = {
    name: "Анна",
    greet() {
        return "Привет, " + this.name
    }
}
console.log(user.greet()) // "Привет, Анна"
```

**Пример 2.** Стрелочная функция (`this` не работает):
```javascript
let user = {
    name: "Анна",
    greet: () => {
        return "Привет, " + this.name
    }
}
console.log(user.greet()) // "Привет, undefined"
```

Я хотел углубиться, но оказалось пока слишком непонятно. Сейчас можно просто запомнить правило: **методы объекта - обычные функции, не стрелки**. Стрелки в методах теряют `this`. Этого достаточно, чтобы не ошибаться, остальное придёт с практикой

Где стрелки полезны: колбэки - берут `this` из внешней функции. Например, внутри `map`, `filter`, `forEach` и других методов, куда мы передаём функцию. Внутри обычных методов для передачи `this` дальше

**Пример 3.**
```javascript
let user = {
    name: "Анна",
    friends: ["Борис", "Вика"],
    greetAll() {
        // метод - обычная функция, this = user
        return this.friends.map(friend => {
            // колбэк - стрелка, this берёт из greetAll, где this = user
            return `${this.name} и ${friend}`
        })
    }
}
console.log(user.greetAll()) // ["Анна и Борис", "Анна и Вика"]
```

Обычно пишут короче:
```javascript
greetAll() {
    return this.friends.map(friend => `Привет, ${friend} от ${this.name}`)
}
```

`friend` - это просто имя переменной, в которую `map` на каждой итерации кладёт один элемент массива. После всех итераций `map` собирает результаты в новый массив. Он возвращается из метода и попадает в `console.log`

`user.greetAll()` - мы обращаемся к этому новому массиву. Метод вызывает `map`, тот создаёт массив и возвращает его

**Задача 1.** Дан объект `filter` с полем `min = 5` и массивом `values = [2, 8, 4, 9]`. Напиши метод, который возвращает только числа больше `min` -> `[8, 9]`

```javascript
let filterObj = {
    min: 5,
    values: [2, 8, 4, 9],
    filterMin() {
        return this.values.filter(value => value > this.min)
    }
}

console.log(filterObj.filterMin()) // [8, 9]
```

Порядок в методе: `return` -> путь к массиву (`this.values`) -> метод массива (`.filter`) -> стрелка с условием. Если метод что-то возвращает, нужен `return`, без него `undefined`

**А как выглядит метод, который ничего не возвращает?**

Вызов без `console.log`, метод просто меняет свойство

**Задача 3.** Дан объект `cinema` с `minRating = 7` и массивом фильмов. Напиши метод, который через цикл `for...of` собирает все жанры из фильмов с рейтингом > 7 в один массив -> `["боевик", "триллер", "драма", "триллер"]`

```javascript
let cinema = {
    minRating: 7,
    films: [
        {title: "A", rating: 8, genres: ["боевик", "триллер"]},
        {title: "B", rating: 6, genres: ["комедия"]},
        {title: "C", rating: 9, genres: ["драма", "триллер"]}
    ],
    getGenres() {
        let result = []

        for (let item of this.films) {
            if (item.rating > this.minRating) {
                result.push(item.genres)
            }
        }

        return result
    }
}

console.log(cinema.getGenres())
```

Цикл `for...of` сам пробегает по массиву и кладёт в `item` очередной фильм. Если рейтинг больше минимального - пушим жанры

**Задача 4.** Дан объект `school` с `minScore = 70` и массивом классов со студентами. Напиши метод, который возвращает массив объектов вида `{class: "10А", topStudents: ["Иван"]}` - только студенты с баллом >= `minScore`

```javascript
let school = {
    minScore: 70,
    classes: [
        {
            className: "10А",
            students: [
                {name: "Иван", score: 90},
                {name: "Оля", score: 60}
            ]
        },
        {
            className: "10Б",
            students: [
                {name: "Петя", score: 80},
                {name: "Маша", score: 55}
            ]
        }
    ],
    getTopStudents() {
        return this.classes.map(cls => ({
            className: cls.className,
            topStudents: cls.students
                .filter(student => student.score >= this.minScore)
                .map(student => student.name)
        }))
    }
}

console.log(school.getTopStudents())
```

Задача не просто учебная, она пригодится на 1-ой работе. Данные с сервера часто приходят вложенными: список категорий, внутри каждой - массив товаров

Что происходит: `this.classes.map` - проходим по каждому классу. Внутри создаём новый объект. `className: cls.className` - копируем имя класса. `topStudents: cls.students...` - фильтруем студентов по баллу и забираем имена

Почему `cls => ({...})`? Скобки вокруг `{}` нужны, чтобы JS понял, что это объект, а не тело функции
