## Этап 1. Всплытие и делегирование событий

Всплытие - это когда событие происходит на элементе, браузер сначала запускает обработчики на этом элементе, потом поднимается к родителю, потом к родителю родителя - и так до document и window

Пример:

```html
<div id="grandparent">
    <div id="parent">
        <button id="child">Кнопка</button>
    </div>
</div>
```

```javascript
const grandparent = document.querySelector("#grandparent");
const parent = document.querySelector("#parent");
const child = document.querySelector("#child");

grandparent.addEventListener("click", function() {
    console.log("Клик по дедушке");
});

parent.addEventListener("click", function() {
    console.log("Клик по родителю");
});

child.addEventListener("click", function() {
    console.log("Клик по кнопке");
});
```

Кликаем 1 раз по кнопке. В консоли появляется 3 сообщения:

```
Клик по кнопке
Клик по родителю
Клик по дедушке
```

**Что произошло:**

1. Кликнули по кнопке - сработал обработчик на кнопке
2. Событие всплыло наверх - сработал обработчик на родителе
3. Всплыло ещё выше - сработал обработчик на дедушке

Событие идёт снизу вверх, как пузырёк в воде. Оно «всплывает» от самого вложенного элемента к самому внешнему

**Зачем это нужно:**

Пример: у тебя список из 100 задач. Вместо 100 обработчиков - вешаешь один на `ul`. Кликнул по любой задаче - событие всплыло до `ul`, и там ты обрабатываешь. Клик по `li` номер 57 - сработал обработчик на `ul`. Это и есть делегирование

**Разница:**

Всплытие: кликнул по кнопке - событие прошло от кнопки к родителю. Это поведение браузера

Делегирование: ты пользуешься всплытием, чтобы обрабатывать события в одном месте на родителе, вместо обработчиков на каждом ребёнке

---

**event.target**

Когда ты вешаешь обработчик на родителя, `event` - это объект с информацией о событии. Внутри него `event.target` - это элемент, по которому реально кликнули

```html
<ul id="list">
    <li>Первый</li>
    <li>Второй</li>
</ul>
```

```javascript
const list = document.querySelector("#list");

list.addEventListener("click", function(event) {
    console.log(event.target);
});
```

Кликнули по «Второй» - в консоли: `<li>Второй</li>`. Кликнули по «Первый» - `<li>Первый</li>`. То есть `event.target` всегда показывает конкретный элемент, на котором произошёл клик, даже если обработчик висит на его родителе

**event.target.tagName**

`tagName` - это свойство элемента, которое возвращает имя его тега заглавными буквами

```javascript
console.log(event.target.tagName);
// "LI" - если кликнули по li
// "BUTTON" - если по кнопке
// "DIV" - если по div
```

Соединяем:

```javascript
const list = document.querySelector("#list");

list.addEventListener("click", function(event) {
    if (event.target.tagName === "LI") {
        console.log("Кликнули по элементу списка");
    }
});
```

Сначала смотрим, по чему кликнули (`event.target`), потом проверяем тег (`tagName`). Если это `LI` - выполняем код. Так один обработчик на родителе понимает, что клик был именно по нужному элементу

**Задача:** При клике на любой `li` зачёркивать его. Новые `li`, добавленные через кнопку, тоже должны зачёркиваться

HTML:

```html
<ul id="list">
    <li>Первый</li>
    <li>Второй</li>
    <li>Третий</li>
</ul>
<button id="add">Добавить</button>
```

JS без делегирования (как мы делали раньше):

```javascript
const list = document.querySelector("#list"); // находим список
const addButton = document.querySelector("#add"); // кнопку 

addButton.addEventListener("click", function() { // обработчик клика по кнопке
    const newLi = document.createElement("li"); // создаём новый li
    newLi.textContent = "Новый"; // даём ему текст
    list.append(newLi); // добавляем в список
});

const items = document.querySelectorAll("li"); // находим все li на странице
for (let item of items) { // проходим по каждому li
    item.addEventListener("click", function() { // вешаем обработчик клика
        item.classList.toggle("crossOut"); // переключаем класс при клике
    });
}
```

Проблема: обработчики вешаются только на те `li`, что были при загрузке. Новые `li` не зачёркиваются

JS с делегированием (правильно):

```javascript
const list = document.querySelector("#list");
const addButton = document.querySelector("#add");

addButton.addEventListener("click", function() {
    const newLi = document.createElement("li");
    newLi.textContent = "Новый";
    list.append(newLi);
});

list.addEventListener("click", function(event) { // один обработчик на весь список
    if (event.target.tagName === "LI") { // проверяем, что кликнули именно по li
        event.target.classList.toggle("crossOut"); // переключаем класс у этого li
    }
});
```

Что убралось:

```javascript
const items = document.querySelectorAll("li");
for (let item of items) {
    item.addEventListener("click", function() {
        item.classList.toggle("crossOut");
    });
}
```

Этот цикл с обработчиками на каждый `li` больше не нужен

Что прибавилось:

```javascript
list.addEventListener("click", function(event) {
    if (event.target.tagName === "LI") {
        event.target.classList.toggle("crossOut");
    }
});
```

Один обработчик на `ul`, внутри проверка через `event.target`, что кликнули именно по `li`

Что осталось без изменений:

```javascript
addButton.addEventListener("click", function() {
    const newLi = document.createElement("li");
    newLi.textContent = "Новый";
    list.append(newLi);
});
```

Создание новых элементов не поменялось

В общем убрали цикл с обработчиками на каждого ребёнка, добавили один обработчик на родителя с проверкой `event.target`. Код стал короче и работает для новых элементов - их не нужно обрабатывать отдельно. Это тоже делегирование

> **Почему `event.classList.toggle("crossOut")` не работает, а `event.target.classList.toggle("crossOut")` работает?**
> 
> Потому что `event` и `event.target` - это разные вещи
> 
> - `event` - это объект события, а не элемент. У него нет classList и других свойств элемента. В нём лежит информация о том, что произошло: какая клавиша нажата, какой элемент кликнули
> - `event.target` - DOM-элемент, на котором реально произошло событие. Именно у элемента есть `classList` и метод `toggle`
> 
> Проще запомнить так: `event` - это «что случилось», `event.target` - «с кем случилось». Классы переключаем у того, с кем случилось, то есть у `event.target`

**contains**

`event.target.classList.contains("класс")` - проверяет, есть ли у элемента указанный класс. Возвращает true или false

```javascript
list.addEventListener("click", function(event) {
    if (event.target.classList.contains("crossOut")) {
        event.target.classList.remove("crossOut");
    } else {
        event.target.classList.add("crossOut");
    }
});
```

Здесь при клике проверяем, есть ли у `li` класс `crossOut`. Если есть - убираем, если нет - добавляем

Ты это уже знаешь из `classList`. В делегировании `contains` используется, чтобы не переключать класс вслепую (как с `toggle`), а действовать по ситуации:

- Есть класс → одно действие
- Нет класса → другое действие

```javascript
// toggle - одно действие на все случаи
event.target.classList.toggle("crossOut");

// contains - разные действия в зависимости от наличия
if (event.target.classList.contains("crossOut")) {
    event.target.classList.remove("crossOut"); // убрали
    output.textContent = "Снято";              // и ещё вывели сообщение
} else {
    event.target.classList.add("crossOut");    // добавили
    output.textContent = "Добавлено";          // и другое сообщение
}
```

Это даёт больше контроля, чем просто `toggle`. Ты сам решаешь, что делать в каждом случае

## Этап 2. Особенности некоторых событий

`focus`, `blur`, `mouseenter`, `mouseleave` не поднимаются к родителю, поэтому делегирование с ними не работает. Для каждого есть всплывающий аналог.

**focus → focusin**

Срабатывает, когда поле получает фокус

```javascript
container.addEventListener("focusin", function(event) {
    event.target.classList.add("focused");
});
```

**blur → focusout**

Срабатывает, когда поле теряет фокус 

```javascript
container.addEventListener("focusout", function(event) {
    event.target.classList.remove("focused");
});
```

**mouseenter → mouseover**

Срабатывает при входе мыши на элемент 

```javascript
container.addEventListener("mouseover", function(event) {
    event.target.classList.add("hovered");
});
```

**mouseleave → mouseout**

Срабатывает при выходе мыши с элемента 

```javascript
container.addEventListener("mouseout", function(event) {
    event.target.classList.remove("hovered");
});
```

> **Почему не сделали всплывающими сразу? Зачем нужны обычные события, если есть всплывающие?**
>
> Потому что `focus` и `blur` - парные события. Когда ты кликаешь по новому полю, одновременно срабатывают два события: `blur` на старом поле (потеряло фокус) и `focus` на новом (получило фокус). Если бы оба всплывали, родитель ловил бы сразу два события на один клик - и было бы непонятно, на что реагировать. В старом коде это могло ломать логику
>
> Поэтому разработчики не стали менять поведение старых событий (иначе сломались бы миллионы сайтов), а добавили новые - `focusin` и `focusout`. Они делают то же самое, но всплывают по одному, без двойственности
>
> Так что `focus` и `blur` остались для случаев, когда обработчик висит прямо на элементе. А для делегирования используют `focusin` и `focusout`
>
> **mouseenter → mouseover**
>
> `mouseenter` и `mouseleave` появились позже, как более удобные аналоги `mouseover` и `mouseout`. Они не всплывают по задумке - чтобы не срабатывать лишний раз, когда мышь переходит между вложенными элементами
>
> Пример. Карточка:
>
> ```html
> <div id="card">
>     <button>Кнопка</button>
> </div>
> ```
>
> Внутри карточки лежит кнопка. Ты ведёшь мышь снаружи, заходишь на карточку, потом наводишь на кнопку
>
> **С `mouseover`:**
>
> - Зашёл на карточку - сработало `mouseover` на карточке
> - Перешёл на кнопку - сработало `mouseover` на кнопке
> - Всего два срабатывания, хотя ты просто провёл мышью внутри одной карточки
>
> **С `mouseenter`:**
>
> - Зашёл на карточку - сработало `mouseenter`
> - Перешёл на кнопку - ничего. Потому что кнопка внутри карточки, а `mouseenter` не реагирует на вложенные элементы
> - Всего одно срабатывание
>
> Вот разница: `mouseover` ловит каждый переход между вложенными элементами, а `mouseenter` - только вход на сам элемент. Поэтому `mouseenter` удобнее, когда нужно понять «мышь внутри карточки или снаружи», не отвлекаясь на кнопки внутри

## Этап 3. Объект event: дополнительные свойства и методы

### event.currentTarget

`event.currentTarget` - это элемент, на котором **висит обработчик события**. В отличие от `event.target`, который показывает, на каком элементе реально кликнули

```html
<div id="parent">
    <button id="child">Кнопка</button>
</div>
```

```javascript
const parent = document.querySelector("#parent");

parent.addEventListener("click", function(event) {
    console.log(event.target);        // <button> - по чему кликнули
    console.log(event.currentTarget); // <div> - на чём висит обработчик
});
```

**Разница:**

- `event.target` - самый глубокий элемент, где произошло событие
- `event.currentTarget` - элемент, на котором висит обработчик

Если кликнуть по кнопке внутри div, а обработчик на div: target = кнопка, currentTarget = div

**Когда это нужно:**

В делегировании, когда хочешь обратиться к родителю, на котором висит обработчик:

```javascript
list.addEventListener("click", function(event) {
    console.log(event.target);        // конкретный li
    console.log(event.currentTarget); // ul, где висит обработчик
});
```

Или если обработчик на одном элементе, а событие всплывает от разных детей - `currentTarget` всегда даст родителя

**Зачем обращаться к родителю**

Потому что иногда нужно изменить родителя, а не ребёнка

Пример: кликнули по кнопке внутри карточки. Нужно выделить всю карточку, а не кнопку

```javascript
card.addEventListener("click", function(event) {
    if (event.target.tagName === "BUTTON") {
        event.currentTarget.classList.toggle("selected"); // выделяем всю карточку
    }
});
```

`event.target` - кнопка. `event.currentTarget` - карточка, на которой висит обработчик. Выделяем карточку, а не кнопку

Или кликнули по `li` внутри `ul`, нужно удалить сам `ul`, а не `li`. Или добавить класс всему списку

```javascript
    if (event.target.tagName === "BUTTON") { // если при клике это кнопка
        output.textContent = "Текст кнопки: " + event.target.textContent + ". Тег родителя: " + event.currentTarget.tagName;
                        // выводим в абзац текст кнопки ↑                          // и тег родителя (div) ↑
        event.target.classList.toggle("active"); // переключаем класс кнопки при клике на неё
    }
})
```

При клике на кнопку вывод будет такой:

`Текст кнопки: кнопка 1. Тег родителя: DIV`

Без условия при нажатии на div вывело бы `Текст кнопки: кнопка 1 кнопка 2 кнопка 3. Тег родителя: DIV`. Потому что клик по родителю - это тоже клик по `container`. `event.target` в этом случае становится сам `container`

### event.type

`event.type` - это строка с названием события, которое произошло. Возвращает то, что ты передал в `addEventListener` первым аргументом. В большинстве случаев ты знаешь, какое событие используешь, и `event.type` не нужен. Он нужен только когда одна функция обрабатывает несколько разных событий - а это редко. Знать его полезно, но применять будешь не часто

```javascript
button.addEventListener("click", function(event) {
    console.log(event.type); // "click"
});

input.addEventListener("input", function(event) {
    console.log(event.type); // "input"
});
```

**Когда пригодится:**

Когда один обработчик ловит несколько событий. Можно повесить одну функцию на разные события и внутри различать их через `event.type`

```javascript
const button = document.querySelector("#button");

function handleEvent(event) {
    if (event.type === "click") {
        console.log("Одинарный клик");
    } else if (event.type === "dblclick") {
        console.log("Двойной клик");
    }
}

button.addEventListener("click", handleEvent);
button.addEventListener("dblclick", handleEvent);
```

> **А как же конфликт click и dblclick?**
> 
> Да, конфликт есть. При двойном клике сначала дважды сработает `click`, потом `dblclick`. Если обработчик один на оба события, вывод будет:
>
> ```
> click
> click
> dblclick
> ```
> 
> Чтобы такого не было, используют таймер: ждут ~250 мс, и если за это время не было второго клика - считают клик одиночным. Но это уже сложно и редко нужно
>
> На практике `click` и `dblclick` на одном элементе не вешают - конфликт неизбежен. Выбирают что-то одно
>
> Так что задача просто для демонстрации `event.type`

**Или на несколько элементов:**

```javascript
function handleAll(event) {
    console.log("Событие: " + event.type);
}

container.addEventListener("click", handleAll);
   // обработчик обращается к функции ↑ с именем handleAll. Так что имя в обработчике должно совпадать с именем функции, с которой работаем
container.addEventListener("input", handleAll);
```

handleEvent и handleAll - это просто имя функции, оно может быть любое. handleEvent с английского «обработчик события»

**Где реально используется:**

Редко. В основном в универсальных обработчиках, когда одна функция обрабатывает разные события. Чаще всего ты вешаешь обработчик на конкретное событие и знаешь, какое именно. Зачем проверять `event.type`, если ты сам написал `"click"` в `addEventListener`?

### event.stopPropagation()

`stopPropagation()` останавливает всплытие события. Обычно событие поднимается от элемента к родителям, но с этим методом оно останавливается на текущем элементе и дальше не идёт

```html
<div id="grandparent">
    <div id="parent">
        <button id="child">Кнопка</button>
    </div>
</div>
```

```javascript
const grandparent = document.querySelector("#grandparent");
const parent = document.querySelector("#parent");
const child = document.querySelector("#child");

grandparent.addEventListener("click", function() {
    console.log("Дедушка");
});

parent.addEventListener("click", function() {
    console.log("Родитель");
});

child.addEventListener("click", function(event) {
    event.stopPropagation();
    console.log("Кнопка");
});
```

Клик по кнопке выведет только `"Кнопка"`. Событие всплыло бы к родителю и дедушке, но `stopPropagation` в обработчике кнопки остановил его сразу

Если бы `stopPropagation` стоял в обработчике родителя:

```javascript
parent.addEventListener("click", function(event) {
    event.stopPropagation();
    console.log("Родитель");
});
```

Тогда клик по кнопке вывел бы `"Кнопка"`, потом `"Родитель"`. Событие поднялось бы до родителя и остановилось. До дедушки не дошло бы

**Когда нужно:**

- Внутри карточки есть кнопка. Клик по кнопке не должен активировать карточку. `stopPropagation` останавливает всплытие к карточке
- Внутри модального окна есть кнопка закрытия. Клик по ней не должен закрывать окно через обработчик на фоне

**Пример с карточкой:**

```html
<div id="card">
    Карточка
    <button id="delete">Удалить</button>
</div>
```

```javascript
const card = document.querySelector("#card");
const deleteButton = document.querySelector("#delete");

card.addEventListener("click", function() {
    console.log("Карточка выбрана");
});

deleteButton.addEventListener("click", function(event) {
    event.stopPropagation(); // не даём клику дойти до карточки
    console.log("Удаление");
});
```

Клик по кнопке «Удалить» выведет только `"Удаление"`. Без `stopPropagation` вывелось бы `"Удаление"`, потом `"Карточка выбрана"` - потому что событие всплыло бы от кнопки к карточке. `stopPropagation` это предотвращает

**preventDefault vs stopPropagation:**

- `preventDefault` - отменяет стандартное поведение браузера (перезагрузку формы, переход по ссылке). Проходили его [тут](DOM/2026-08-30-04-события.md) во втором этапе
- `stopPropagation` - останавливает всплытие события к родителям

Они делают разное. Можно использовать вместе:

```javascript
// Ссылка внутри карточки ведёт на внешний сайт.
// При клике на карточку - она выделяется.
// При клике на ссылку - переход не происходит, карточка не выделяется, в консоль выводится "Ссылка обработана".

const card = document.querySelector("#card");
const link = document.querySelector("#link");

card.addEventListener("click", function() {
    card.classList.toggle("selected");
});

link.addEventListener("click", function(event) {
    event.preventDefault();    // отменяет переход по ссылке
    event.stopPropagation();   // не всплывать к карточке
    console.log("Ссылка обработана");
});
```

**Зачем ссылка, если по ней нельзя перейти?**

`preventDefault` можно вызывать не всегда, а при условии. Например, ссылка ведёт на внешний сайт, но если пользователь не авторизован - переход отменяется, и выводится «Войдите в аккаунт». Или ссылка на удаление - сначала подтверждение, потом переход

Или ссылка на якорь внутри страницы, но с плавной прокруткой через JS. Тогда `preventDefault` отменяет стандартный резкий прыжок, и ты сам делаешь плавную прокрутку

### closest()

`closest` - метод элемента, который ищет ближайшего родителя (включая сам элемент) по CSS-селектору. Поднимается вверх по дереву DOM, пока не найдёт подходящий. Если не нашёл - возвращает `null`

```html
<div class="card">
    <div class="card-body">
        <button class="delete">Удалить</button>
    </div>
</div>
```

```javascript
const button = document.querySelector(".delete");
const card = button.closest(".card");

console.log(card); // <div class="card">...</div>
```

`button.closest(".card")` поднимается от кнопки: сначала проверяет саму кнопку (нет класса `card`), потом `card-body` (нет), потом `card` (есть). Возвращает этот div

**Зачем нужно:**

Когда кликнули по кнопке внутри карточки, а работать нужно с самой карточкой. Через `closest` находишь родителя и делаешь с ним что нужно

**Пример с делегированием:**

```javascript
container.addEventListener("click", function(event) {
    if (event.target.tagName === "BUTTON") {
        const card = event.target.closest(".card");
        card.classList.toggle("selected");
    }
});
```

Кликнули по кнопке - нашли карточку через `closest` - выделили её. Кнопок может быть много, обработчик один, а `closest` всегда найдёт нужную карточку

**Пример с вложенностью:**

```html
<div class="card">
    <p>Внешняя карточка</p>
    <div class="card">
        <p>Внутренняя карточка</p>
        <button>Кнопка</button>
    </div>
</div>
```

```javascript
const button = document.querySelector("button");
const card = button.closest(".card");

console.log(card); // найдёт ВНУТРЕННЮЮ карточку - она ближайшая
```

**Что такое вложенность:**

Это когда один элемент находится внутри другого. Например, `div` внутри `div`, или кнопка внутри `div`. Уровней может быть много: `div` → `div` → `button`

**Зачем это нужно:**

В реальных интерфейсах элементы вложены друг в друга. Карточка внутри списка, кнопка внутри карточки, иконка внутри кнопки. И когда кликаешь по чему-то в глубине, нужно понять - к какому родителю это относится

`closest` ищет **ближайшего** родителя. Если карточек несколько (одна внутри другой), `closest(".card")` вернёт ту, что ближе к кнопке - внутреннюю. Не внешнюю

Это важно, когда у тебя сложная структура: например, список задач, внутри задачи - подзадачи, внутри подзадачи - кнопка. `closest` найдёт именно ту подзадачу, где нажали кнопку, а не весь список

&nbsp;

**Задача.** Внутри карточки есть кнопка и абзац с классом `title`. При клике на кнопку - найди карточку через `closest`, потом найди внутри неё `title` через `querySelector` и измени его текст на `"Изменено"`

HTML:

```html
<div id="container">
    <div class="card">
        <p class="title">Название 1</p>
        <button>Изменить</button>
    </div>
    <div class="card">
        <p class="title">Название 2</p>
        <button>Изменить</button>
    </div>
</div>
```

CSS:

```css
.card {
    border: 1px solid gray;
    padding: 10px;
    margin: 5px;
}
```

JS:

```javascript
const container = document.querySelector("#container");

container.addEventListener("click", function(event) {
    if (event.target.tagName === "BUTTON") {
        const card = event.target.closest(".card"); // поднимаемся от кнопки до карточки
        const title = card.querySelector(".title"); // ищем title внутри карточки
        title.textContent = "Изменено";             // меняем текст
    }
});
```

**Разбор:**

Если карточка одна, то можно вешать обработчик прямо на неё. Но если карточек несколько - нужен общий контейнер или цикл по карточкам. Иначе обработчик будет только на первой

> **Почему нужна проверка `event.target.tagName === "BUTTON"`:**
> 
> Обработчик висит на контейнере, а не на кнопке. Значит, он срабатывает при **любом** клике внутри - по карточке, по абзацу, по пустому месту. Без проверки код будет срабатывать везде, а не только там, где нужно
> 
> Проверка `event.target.tagName === "BUTTON"` отсеивает всё лишнее. Сработает только когда кликнули именно по кнопке. Дальше уже идёт `closest`, который находит карточку. Поэтому проверка обязательна

`event.target.closest(".card")` - поднимаемся вверх от кнопки и находим ближайшую карточку. Именно ту, в которой кликнули, а не первую в списке

`card.querySelector(".title")` - теперь спускаемся вниз, внутрь этой карточки, и находим `title`. Ищем только внутри `card`, а не по всей странице

> **В каких случаях мы пишем `querySelector`, а когда `event.target.closest`?**
>
> - `querySelector` - когда ищем элемент **заранее**, до события. Знаем, где он, и хотим его получить. Ищет **внутри** указанного элемента или по всей странице, если от `document`
> - `event.target.closest` - когда уже произошло событие, и нужно **подняться** от элемента, по которому кликнули, к его родителю. Ищет **снаружи**, вверх по дереву
> 
> В этой задаче оба нужны: `closest` находит карточку (вверх от кнопки), `querySelector` находит `title` (вниз внутри карточки)

> На примере:
>
> Хочу найти карточку, чтобы повесить на неё обработчик → `querySelector(".card")`
>
> Кликнули по кнопке внутри карточки, хочу найти саму карточку → `event.target.closest(".card")`
>
> Кликнул по карточке, хочу найти абзац внутри неё → `card.querySelector("p")`

```javascript
const card = document.querySelector(".card");

card.addEventListener("focusout", function(event) {
    if (event.target.tagName === "INPUT") {
        const foundCard = event.target.closest(".card");

        if (event.target.value === "") {
            foundCard.classList.add("filled");
        } else {
            foundCard.classList.remove("filled");
        }
    }
});
```

```javascript
const list = document.querySelector("#list");
const output = document.querySelector("#output");

list.addEventListener("click", function(event) {
    if (event.target.tagName === "BUTTON") {
        const task = event.target.closest("li");

        if (task.classList.contains("crossOut")) {
            task.remove();
            output.textContent = "Осталось: " + list.querySelectorAll("li").length; // считаем оставшиеся li внутри списка и выводим в абзац
        } else {
            task.classList.add("crossOut");
        }
    }
});
```

**Что делает `event.target.closest("li")`**

`closest` не берёт первый `li` в списке. Он находит **ближайшего родителя** от того элемента, по которому кликнули, в момент клика

1. Кликнули по кнопке внутри какого-то `li` - `event.target` это конкретная кнопка
2. `event.target.closest("li")` поднимается от неё вверх и находит **тот самый** `li`, внутри которого кнопка
3. Дальше работаем с этой задачей: зачёркиваем, удаляем

Если написать `const task = document.querySelector("li")` до обработчика, это всегда будет **первый** `li` в списке. Клик по кнопке во втором `li` всё равно вернул бы первый. Поэтому `closest` вызывается внутри обработчика, для каждого клика заново
