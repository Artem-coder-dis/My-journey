## Область видимости и TDZ


### Этап 1: Область видимости

Область видимости - это то, где переменная доступна. Есть три вида:
- Глобальная - переменная видна везде
- Функциональная - переменная видна только внутри функции
- Блочная - переменная видна только внутри `{}`

&nbsp;

**Глобальная область видимости**

Переменная объявлена снаружи всех функций и блоков - видна везде

**Пример 1**

```javascript
let name = "Анна";

function greet() {
    console.log("Привет, " + name); // видит глобальную name
}

greet(); // "Привет, Анна"
console.log(name); // "Анна"
```

&nbsp;

**Функциональная область видимости**

Переменная, объявленная внутри функции, не видна снаружи

**Пример 2**

```javascript
function test() {
    let secret = "пароль";
    console.log(secret); // "пароль" - внутри видна
}

test();
console.log(secret); // Ошибка! ReferenceError: secret is not defined
```

&nbsp;

**Блочная область видимости**

`let` и `const` видны только внутри блока `{}`. `var` - игнорирует блоки

**Пример 3**

```javascript
{
    let a = 1;
    const b = 2;
    var c = 3;
}

console.log(a); // Ошибка! a не существует
console.log(b); // Ошибка! b не существует
console.log(c); // 3 - var утёк из блока
```

</details>

**Пример 4** 

```javascript
for (let i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 100); // 0 1 2
}

for (var j = 0; j < 3; j++) {
    setTimeout(() => console.log(j), 100); // 3 3 3
}
```
 
Первый цикл (`let`): хоть и технически переменная `let` на самом деле создаётся внутри цикла, а не в условии, но всё равно имеет особое поведение - на каждой итерации создаётся новая переменная `i`, которая получает значение предыдущей. Это не перезапись, а именно создание новой переменной с тем же именем. Поэтому функции внутри `setTimeout` видят каждая свою `i: 0, 1, 2`

Второй цикл (`var`): переменная `j` одна на весь цикл. Она меняется: 0, 1, 2, 3. Когда цикл закончился, `j` осталось равно 3. Функции внутри setTimeout срабатывают после цикла и видят уже финальное значение 3. Поэтому вывод: 3, 3, 3

Цикл с `var`  выполняется так:

`j = 0` → `0 < 3` → да → выполняем тело → `j++ → j = 1`

`j = 1` → `1 < 3` → да → выполняем тело → `j++ → j = 2`

`j = 2` → `2 < 3` → да → выполняем тело → `j++ → j = 3`

`j = 3` → `3 < 3` → нет → цикл остановился

Тело выполнилось 3 раза (когда `j` было 0, 1, 2). Но после последнего `j++` переменная стала равна 3. Цикл проверяет условие, видит, что `3 < 3` - ложь, и останавливается. А переменная `j` осталась равна 3

&nbsp;

**Задача 1.** Что выведет код? Объясни почему

```javascript
let x = "глобальная";

function test() {
    let x = "локальная";
    console.log(x); // ?
}

test();
console.log(x); // ?
```

<details>
<summary>Ответ</summary>

`"локальная"`, потом `"глобальная"`

Внутри функции объявлена своя `x = "локальная"`, она не трогает глобальную. Функция выводит `"локальная"`. Снаружи функции выводится глобальная `"глобальная"`

</details>

**Задача 2.** Что выведет код? Объясни почему

```javascript
let a = 1;

function outer() {
    let a = 2;
    
    function inner() {
        let a = 3;
        console.log(a); // ?
    }
    
    inner();
    console.log(a); // ?
}

outer();
console.log(a); // ?
```

<details>
<summary>Ответ</summary>

`3`, `2`, `1`

`inner()` выводит свою `a = 3`. После `inner()` внутри `outer()` выводится `a = 2` (переменная `outer`). Снаружи всех функций выводится глобальная `a = 1`

</details>

**Задача 3.** Что выведет код? Объясни почему

```javascript
if (true) {
    let x = 1;
    const y = 2;
    var z = 3;
}

console.log(x); // ?
console.log(y); // ?
console.log(z); // ?
```

<details>
<summary>Ответ</summary>

`x` и `y` - ошибка `ReferenceError`, `z` - `3`

`x` и `y` объявлены через `let` и `const` внутри блока - снаружи их нет, будет ошибка. `z` объявлен через `var` - он игнорирует блок и виден снаружи, выведет `3`. Первые два `console.log` вызовут ошибку, до третьего выполнение не дойдёт

</details>

**Задача 4.** Что выведет код? Объясни почему

```javascript
let count = 10;

function increment() {
    count = 20;
}

increment();
console.log(count); // ?
```

<details>
<summary>Ответ</summary>

`20`

`count` меняется на 20 только потому, что сработал вызов функции. Без вызова `count` так бы и осталось 10
</details>

**Задача 5.** Что выведет код? Объясни почему

```javascript
let count = 10;

function increment() {
    let count = 20;
}

increment();
console.log(count); // ?
```

<details>
<summary>Ответ</summary>

`10`

Внутри функции создана своя `count = 20`, она не трогает глобальную. После вызова функции глобальная `count` осталась `10`. Локальная переменная не повлияла на глобальную

</details>

**Поднятие (hoisting)**

`var` и Function Declaration «всплывают» вверх своей области видимости. JS как будто перемещает их объявление в начало кода, но оставляет присваивание на месте

**С var:**

```javascript
console.log(x); // undefined - не ошибка!
var x = 5;
console.log(x); // 5
```

JS видит это так:

```javascript
var x;          // объявление всплыло вверх
console.log(x); // undefined
x = 5;          // присваивание осталось на месте
console.log(x); // 5
```

`var` всплывает с `undefined`. Переменная уже существует, но без значения - поэтому `undefined`, а не ошибка

То есть допустим мы объявляем `var` на строке 50 в глобальной области видимости, для JS она автоматически переносится на 1-ую строку, выше всех. `var` переносится в самый верх **своей** области видимости 

**С Function Declaration:**

```javascript
greet(); // "Привет!" - работает до объявления!

function greet() {
    console.log("Привет!");
}
```

Function Declaration всплывает целиком - и объявление, и тело. Поэтому функцию можно вызвать до её объявления в коде

**let и const НЕ всплывают так:**

```javascript
console.log(x); // Ошибка! ReferenceError
let x = 5;
```

Они тоже всплывают, но попадают в TDZ (временную мёртвую зону). Обращение к ним до объявления вызывает ошибку, а не `undefined`. Это безопаснее - ошибка сразу видна

### Этап 2: Временная мёртвая зона (TDZ)

TDZ (Temporal Dead Zone) - это период между входом в область видимости и моментом, когда переменная объявлена через `let`/`const`. В это время переменная существует, но к ней нельзя обратиться

**Пример ошибки:**

```javascript
console.log(x); // ReferenceError!
let x = 5;
```

JS знает, что `x` будет объявлен, но ещё не дошёл до строки `let x = 5`. Обращение к переменной в TDZ вызывает ошибку

**С var такого нет:**

```javascript
console.log(x); // undefined
var x = 5;
```

`var` всплывает с `undefined`, ошибки нет. Но это не значит, что `var` лучше - такие баги сложнее находить. `let`/`const` падают сразу и громко, что помогает быстрее найти проблему

**Задача 1.** Что выведет код? Объясни почему

```javascript
function test() {
    console.log(a); // ?
    let a = 10;
    console.log(a); // ?
}

test();
```

<details>
<summary>Ответ</summary>

Ошибка `ReferenceError: Cannot access 'a' before initialization`

Внутри функции объявлена `let a`. С начала функции и до строки `let a = 10` переменная находится в TDZ. Первый `console.log(a)` вызывает ошибку. Второй `console.log` не выполнится - код упадёт раньше

</details>

**Задача 2.** Что выведет код? Объясни почему

```javascript
let x = 1;

{
    console.log(x); // ?
}
```

<details>
<summary>Ответ</summary>

`1`

Внутри блока нет своего `let x`. JS идёт во внешнюю область и находит глобальную `x = 1`. TDZ нет, потому что в блоке нет объявления

</details>

**Задача 3.** Что выведет код? Объясни почему

```javascript
let x = 1;

{
    console.log(x); // ?
    let x = 2;
}
```

<details>
<summary>Ответ</summary>

Ошибка `ReferenceError: Cannot access 'x' before initialization`

Внутри блока есть `let x = 2`. JS видит это объявление и резервирует переменную, не обращаясь к глобальной. Но `console.log(x)` стоит до объявления - переменная в TDZ. Ошибка

</details>

**Задача 4.** Что выведет код? Объясни почему

```javascript
function test(a = console.log("Привет"), b = 2) {
    return a + b;
}

test();
```

<details>
<summary>Ответ</summary>

`"Привет"`, потом `NaN`

Параметры по умолчанию вычисляются слева направо. `a = console.log("Привет")` - `console.log` выполняется и возвращает `undefined`, поэтому `a = undefined`. Выводится `"Привет"`. Потом `b = 2`. Результат `undefined + 2` → `NaN`

</details>

**Задача 5.** Что выведет код? Объясни почему

```javascript
function test(a = b, b = 2) {
    return a + b;
}

test();
```

<details>
<summary>Ответ</summary>

Ошибка `ReferenceError: Cannot access 'b' before initialization`

Параметры вычисляются слева направо. `a = b` - но `b` ещё не объявлен, он в TDZ. Ошибка. До выполнения тела функции дело не дойдёт

</details>

---

**Итог:**

- `let`/`const` живут в блоке, `var` - в функции или глобально
- Переменная ищется от внутренней области к внешней
- Внутри функции/блока можно создать переменную с тем же именем - она не тронет внешнюю
- TDZ - период от входа в область видимости до объявления `let`/`const`
- Обращение к переменной в TDZ вызывает ошибку
- `var` не имеет TDZ - всплывает с `undefined` (хуже для отладки)
